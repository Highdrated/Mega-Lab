Why it works this way

Why the two panels? A PHP page always has two sides: a request coming in (the customer's order) and a response going out (the plated dish). The left panel is your kitchen — the PHP. The right panel is the customer placing an order. In real life a browser and web server sit between them; here this tool plays both.

How the order reaches your code. When you hit Send, the tool fills PHP's built-in request arrays before your script runs: $_GET for fields sent in the URL, $_POST for fields sent by a form, and $_SERVER["REQUEST_METHOD"] for which kind it was. That is exactly what a real web server does the instant a request arrives — it hands your script these ready-made arrays. Your code just reads the order off them.

Why the response looks like a real web page. Because it is one. Everything your PHP echoes — including the HTML tags — is plain text. PHP hands that text back, and a browser renders it into a page. The Page tab shows the rendered result; the Raw HTML tab shows the exact text PHP produced, so you can see there's no magic — just text becoming a page.

Why htmlspecialchars() is in the sample. The name comes from the customer — a stranger. Wrapping it on the way out means if someone submits <script> as their name, it shows as harmless text instead of running. Output hygiene, every time, as a reflex.

Heads up: open this from a web address (your GitHub Pages, or a local server) — not by double-clicking; file:// blocks the engine. First send downloads the PHP engine once, then it's instant. If it can't load, the status turns red — open the console (F12), copy the error, and send it to me.
